VOC Pick Up & Delivery Request — User Manual

Version 1.0 • Built-in guide for Employees, Section Managers, Supervisors, and Admin users.
Manual Contents

1. Getting Started

VOC Pick Up & Delivery Request is used to create, review, approve, process, track, and report asset movement requests.

Available Roles

  • Employee: Create, save, submit, edit Draft/Rejected requests, and track status.
  • Section Manager: Review requests for assigned sections and approve or reject them.
  • Admin: Process approved requests and mark work completed.
Tip: Use the tabs at the top of the application to move between Dashboard, role-specific work screens, Reports, Help, and About.

2. System Workflow

Each status change is recorded in the request activity history so users can see what happened and when.

3. Employee Guide

1
Open New Request

Select New Request from the navigation.

2
Select Request Type

Choose Delivery when assets are being sent to a location or Pickup when assets need to be collected.

3
Complete Request Information

Enter Division, Section, Priority, Location, Requested Date, Preferred Time, Site Contact, Phone/Extension, and Business Reason / Instructions.

4
Add Devices

Select Asset Type, enter Asset Tag / ID, optional Serial Number, and Quantity. Select + Add Device. Repeat for additional devices.

5
Save or Submit

Select Save Draft if work is not complete. Select Review & Submit when ready.

6
Review

Confirm requester information, device lines, quantity, location, date, contact, and instructions.

7
Submit

Select Confirm & Submit. The request receives a unique Request ID and routes to Section Manager Approval.

Important: Employees can edit requests only when they are in Draft or Rejected status.

4. Section Manager Guide

  1. Open Section Manager Approval.
  2. Review each Pending Section Manager request.
  3. Check employee information, request type, priority, requested date, location, devices, quantity, site contact, and instructions.
  4. Select Approve when the request is valid and ready for Operations Processing.
  5. Select Reject when the employee needs to make a correction.
  6. Use Reports to monitor overall workload and status.
Approved requests move to the Admin queue. Rejected requests return to the employee for editing and resubmission.

5. Admin Guide

  1. Open Operations Processing.
  2. Review requests with Approved status.
  3. Select Start Processing when operational work begins.
  4. Coordinate asset preparation, delivery, pickup, or handoff as required.
  5. Open the request again to verify details before completion.
  6. Select Mark Completed after the work is finished.
  7. Use Dashboard and Reports for monitoring and CSV export.

6. Devices / Assets

One request can contain one or many device lines. This avoids creating separate requests when several devices are moving to the same location under the same business request.

Device Fields

  • Asset Type: Category of equipment.
  • Asset Tag / ID: Unique identifier for the asset or device line.
  • Serial Number: Optional hardware serial number.
  • Quantity: Number of items represented by the line.

Use Edit to return a device line to the entry area for changes. Use Remove to delete it from the request before submission.

Duplicate Asset Tag / ID values are blocked within the same request.

7. Dashboard & Search

The Dashboard is the main tracking screen. It shows request counts and a searchable request table.

Search

The search box can match Request ID, Employee, Employee ID, Division, Section, Request Type, Priority, Status, Asset Type, Asset Tag, Serial Number, Location, Site Contact, Notes, and dates.

  • Type one word for a broad search.
  • Type multiple words to narrow results.
  • Use the Status filter together with search.
  • Select Clear to reset search and status filtering.
  • The result count shows how many rows match the current search.

Open Request

Select Open to view full request details, devices, current status, and activity history.

CSV files can be opened in Excel for additional filtering, pivot tables, analysis, or reporting.

9. Request Status Definitions

  • Draft: Request is saved but has not been submitted.
  • Pending Section Manager: Employee submitted the request and it is waiting for Section Manager review.
  • Approved: Section Manager approved the request and it is ready for Operations Processing.
  • Rejected: Section Manager returned the request to the Employee for correction.
  • Operations Processing: Admin has started operational processing.
  • Completed: Pick Up / Delivery work is finished.

10. Request History

Each request includes an Activity History. It records major actions such as Draft creation, submission, approval, rejection, Admin processing, completion, and resubmission.

Open a request from the Dashboard to review the timeline.

11. Troubleshooting

I cannot submit the request.

Confirm all required fields are completed, at least one device has been added, Employee ID is valid, and Requested Date is not in the past.

I cannot find a request.

Clear the Dashboard search and Status filter, then search again using the Request ID, Employee ID, Asset Tag, or Location.

I cannot edit a request.

Employees can edit only Draft or Rejected requests. Requests already submitted or being processed follow the controlled workflow.

I do not see Reports.

The Reports tab is available to Supervisor and Admin roles.

CSV export shows fewer rows than expected.

Dashboard CSV export follows the current search and status filter. Clear filters before exporting all visible requests.

My demo data disappeared or changed.

Version 1.0 currently stores testing data in the browser. Clearing browser storage can remove locally stored demo requests.

12. Admin User & Access Management

Admins can maintain application users from the User Management tab. For demo testing, choose Admin on the login screen; the system will automatically load Admin Demo ID 1009001.

  • Add new users.
  • Edit employee name, Employee ID, role, division, and active status.
  • Grant access to one or many sections.
  • Activate or deactivate access.
  • Delete users when appropriate.

Multi-Section Supervisor Access

A Supervisor can be granted multiple sections. The Section Manager Approval queue and dashboard will show requests for those granted sections.

Example: an Operations Supervisor can be granted Asset Management, Warehouse Operations, Quality Assurance (QA), and Logistics & Field Support at the same time.

13. Security & Production Notes

Version 1.0 is a functional browser-based demonstration. The current role selector and browser storage are intended for testing and design validation.

Recommended Production Design

Microsoft Entra ID → VOC Web Application → Secure API → Azure SQL or Dataverse

  • Use organization sign-in instead of a role dropdown.
  • Determine Employee, Supervisor, and Admin permissions from authenticated identity or security groups.
  • Store requests, devices, and history in Azure SQL or Dataverse.
  • Enforce approval/status permissions on the server, not only in the browser.
  • Protect database credentials and application secrets.

What This System Does

VOC Pick Up & Delivery Request is designed to manage operational requests for moving equipment and assets between locations. It provides one place for request submission, approval, processing, completion, history, reporting, and export.

Core Features

  • Role-based Employee, Supervisor, and Admin experience
  • Admin User & Access Management
  • Multi-section access grants for Supervisors
  • Delivery and Pick Up request types
  • One request with multiple devices
  • Draft saving and resubmission
  • Section Manager approval and rejection
  • Admin processing and completion
  • Dashboard status tracking
  • Search and status filtering
  • Operational Reports Dashboard
  • CSV export
  • Request receipt
  • Activity history / audit trail

Data Captured

  • Request ID
  • Employee Name and Employee ID
  • Division and Section
  • Delivery or Pick Up
  • Priority
  • Location
  • Requested Date and Preferred Time
  • Site Contact and Phone
  • Business Reason / Instructions
  • Asset Type, Asset Tag, Serial Number, and Quantity
  • Status, Submitted Date, Updated Date, and Request History

Version 1.0 Scope

Version 1.0 establishes the initial complete user workflow and user interface for request management. It includes role-based workflow simulation, multi-device requests, approval processing, dashboards, reports, search, history, and CSV export.

Production deployment should replace browser local storage and demo role selection with a secure backend database and organization authentication.

Recommended Production Architecture

Microsoft 365 / Entra ID → VOC Web App → Secure API → Azure SQL or Dataverse

This keeps authentication, role permissions, request records, asset records, approvals, and request history centralized and secure.
